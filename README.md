# 拼豆图纸生成器（微信小程序）

把任意图片转成拼豆图纸的微信小程序。手机出图纸、按色号分批拼、拼完打卡分享。

本项目是 [Zippland/perler-beads](https://github.com/Zippland/perler-beads) 网页版的微信小程序移植版。
算法参考了原项目，代码是从零重写的原生小程序实现，并针对手机场景增加了原版没有的功能。

## 功能

### 出图纸

- 选图或拍照，自动切成像素网格并映射到店家色号
- 参数用「豆子尺寸 + 成品宽度」，格子数自动算
  （不写「横轴多少格」——拼豆的人想的是成品多大）
- 支持 5 个店家色号体系：MARD、COCO、漫漫、盼盼、咪小窝，共 291 个标准色
- 自定义色板，只勾你手上有的颜色，图纸就只用这些色号
- 一键去背景；排除不想要的颜色，自动重映射到最近似可用色
- 导出图纸 PNG，带色号标注、网格线、坐标轴和底部采购清单
- 实时预览，支持缩放，点格子看色号

### 拼豆进度模式

定位是「按色号分批拼」：倒出一盒 A01，把它全部摆完，再换下一盒。
在纸质图纸上找分散在几十处的同一个色号非常费眼，这个模式解决这一步。

- 只看当前色，其他色号不画，图纸上只剩当前色号的豆子
- 顶部显示「现在拼 A01，还剩 128 颗」
- 「这盒拼完了」按钮，把剩下的一次性标完，自动跳下一个色号
- 点击标记单格，长按标记整个连通色块，可撤销
- 进度自动保存，切后台、锁屏、杀掉小程序都不会丢

### 项目列表

「我的拼豆」列出所有作品，带缩略图和进度，点哪个继续哪个。

### 作品打卡与分享

- 拼完拍照，生成打卡卡片，保存相册或分享
- 把图纸分享给好友：好友点开小程序卡片，能直接存进自己的项目，自己拼
  （图纸传微信云开发，不依赖自建服务器）

## 和原版的区别

技术上最大的不同是这个不是网页而是小程序。原版用 Next.js 加浏览器 Canvas，
这里用原生 WXML/WXSS/JS 加小程序 Canvas 2D。

### 原版文档与代码不符

原项目的 README 和 CLAUDE.md 描述了三处功能，代码里没有实现。
这里按真实代码移植，并把缺的那一步补上了。

| 文档写的 | 代码里实际是 |
| --- | --- |
| 168/144/96 预设色板 | 不存在，默认用全部 291 色 |
| `BACKGROUND_COLOR_KEYS` 固定背景色号表 | 不存在，实际是取四条边上出现最多的颜色再做洪水填充 |
| 颜色合并用 BFS 连通区域 | 不是 BFS，是全局按频率降序两两比色距、低频并入高频 |
| 用 RGB 欧氏距离 | 是 Oklab 欧氏距离乘以 100 |

其中「BFS 连通区域合并」是让图纸不脏的关键一步，用来去掉孤立的单格杂点，
原版代码里没有，这里补上了（`utils/cleanup.js`）。

### 调整过的默认值

原版有几个默认值直接抄过来会出问题，实测后改了。

| 参数 | 原版 | 这里 | 原因 |
| --- | --- | --- | --- |
| 颜色合并阈值 | 30 | 8 | 30 在 Oklab 乘 100 的尺度上是色板相邻色号间距的 11 倍，会把绿植并进棕色。一张 51 色的照片会塌成 3 色，其中 79% 是近黑 |
| 格子数 | 100 | 按成品尺寸算 | 100 时一格盖住原图 19 乘 19 像素，瀑布、远景建筑这类细结构会被平均掉 |

### 新增的

- 全部进度模式、项目列表、打卡、分享（原版的专注模式进度不落盘，刷新即归零）
- 成品尺寸导向的参数（原版是「横轴切割数量」）
- 内容安全检测（原版是网页，没有这个要求）

## 运行

### 前置

- 微信开发者工具，基础库 2.16.1 及以上（用到 `createOffscreenCanvas`）
- 一个小程序 AppID，个人主体即可，纯本地开发也可以用测试号

用微信开发者工具「导入项目」，选择本目录。

不需要 npm install。项目没有构建步骤，`utils/` 全是纯 CommonJS，
小程序和 Node 都能直接 require。

### 云开发

只影响「分享图纸给好友」，不做也能跑，其他功能全部本地运行。

1. 微信公众平台，开发，云开发，开通后建一个环境
2. 云开发控制台，数据库，新建集合 `patterns`
3. 该集合权限设为「所有用户可读，仅创建者可读写」
   默认的「仅创建者可读写」会让好友读不到图纸
4. 把环境 ID 填进 `utils/cloud.js` 的 `ENV_ID`
5. 开发者工具里右键 `cloudfunctions/checkContent`，选「上传并部署：云端安装依赖」

没配 `ENV_ID` 时，云功能会自动隐藏或提示，其他功能不受影响。

### 数据怎么存

图纸和进度分开两个 key 存。

```
beadProjects        项目索引，首页列表用
beadProject_<id>    图纸，只写一次，压缩成色号表加每格下标再转 base64
beadProgress_<id>   进度，频繁写，位图每格 1 bit
```

60 乘 34 的图纸约 6KB，300 乘 169 约 145KB，进度只有几百字节到 8KB。

拆两个 key 是必要的。拼的过程中只有进度在变，合在一起的话每次保存都要重写整张图纸。

进度每次改动立刻落盘。数据小，同步写约 1 毫秒，不需要节流。
用户直接杀掉小程序时 `onHide` 不一定触发，节流窗口里的改动会丢。

项目没有构建步骤，`utils/` 里的逻辑全部可以在 Node 里直接测，不需要模拟器。

### 开发期工具

放在 `tools/`，不进小程序包。

| 工具 | 用途 |
| --- | --- |
| repro.js | 在 Node 里用小程序同一套算法跑真实图片并出图，一步区分「算法错」还是「Canvas 采样错」 |
| render-export.js | 把导出图纸在 Node 里渲染出来，不开模拟器就能看排版 |

## 已知问题

### 画布显示

本项目环境里，`<canvas type="2d">` 出现过「内容确实画上去了
（`getImageData` 能回读到正确颜色）、节点稳定、位置尺寸都对，但屏幕上不显示」的情况。
排查了 8 轮（排除颜色、时序、节点替换、`overflow:hidden`、`wx:if`、视口尺寸、
清缓存、重启），没有找到根因。

现在的做法是绕过去：渲染到隐藏画布，用 `canvasToTempFilePath` 导出 PNG，
再用 `<image>` 显示（`utils/gridImage.js`）。这条路径和「导出图纸」是同一套机制。

代价是改一次内容要重新出图，约 50 到 200 毫秒，所以缩放用档位按钮而不是双指实时缩放，
点格子标记后防抖 350 毫秒再重出图。

不要把它改回 canvas 直接显示，会撞同一堵墙。
如果哪天在真机上确认 canvas 显示正常，可以回退，性能会更好。
