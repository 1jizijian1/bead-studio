## 今天做了什么

### 1. 上传代码 → 代码质量检查没过

提示「**代码压缩 → 对JS文件进行压缩：未通过**」。

原因：`project.config.json` 里 `"minified": false` —— 这是「上传代码时自动压缩」的开关，
一直是关的，所以传上去的是**未压缩的源码**。我们项目没有构建步骤，JS 就是原始文件，
只能靠上传时压缩。

→ 改成 `true`。

**顺带搞清了**：「代码质量」那一栏是**建议项，不是提交审核的门槛**。就算红着也能提交。

### 2. 填「用户隐私保护指引」

这是新版本小程序的**硬门槛**，不填发不出去。逐项填了：
- 相册（仅写入）→ 保存图纸、打卡图
- 收集照片/视频 → 转图纸 + 打卡图配图
- 存储期限选了「最短必要时间」（不是「固定 N 天」——**填固定天数反而给自己挖坑**，
  第 N+1 天数据还在就违约了）
- 联系方式（必填，不填提交不了）

### 3. 提交审核 → 被拒两处

**① 名称：「bean拼豆」被判成组织机构名称**

> 你申请的名称为组织机构名称，暂不支持以个人身份申请

个人主体的小程序不能用像企业/机构的名字。要用「昵称/创意词 + 功能词」这种形式。
（另一条路：有**个体工商户营业执照**就能用组织主体注册，那这类名字就能用。）

**② 内容安全：UGC 类小程序未接内容安全 API**

> 你的小程序【图片】功能在进行内容安全验证时，存在信息安全风险……
> 确保已接入内容安全API

**这条是关键认知**：我们的「分享图纸给好友」让用户能把内容**发布出去**（好友能看到），
这就属于 **UGC**。微信的规矩是：**凡是用户能发布出去的内容，发布前都要过内容安全接口**。

→ 接了 `security.imgSecCheck`（详见下面）。

### 4. 接入内容安全检测

**做法**：
- `cloudfunctions/checkContent`：云函数，用**云调用**调 `security.imgSecCheck`
  （走云调用就不用自己管 access_token）
- `utils/contentCheck.js`：客户端送检。图片先传**云存储**拿 fileID 再交给云函数
  （绕开 callFunction 的请求体大小限制），检完删掉临时文件
- 接进分享流程：「分享图纸给好友」送检图纸图；「分享打卡图」送检缩小版

**踩的坑**：
1. **云调用必须在 `config.json` 里声明权限**：
   ```json
   { "permissions": { "openapi": ["security.imgSecCheck"] } }
   ```
   不声明会报「无权限调用」。
2. **接口限制图片 ≤1MB**，而打卡图含实拍照片会超 → 送检时导一张 360×540 的 JPEG 缩小版
   （给 `canvasHelper.exportCanvasToFile` 加了 `opts` 参数）
3. **上传云函数报 `read ECONNRESET`** —— 是**代理问题**（这台机器跑着 Clash）。
   开发者工具默认走系统代理，连腾讯云时被重置。
   → 设置 → 代理设置 → 「不使用任何代理」→ 重启工具。
   （和之前 git 卡在证书吊销检查是同一类问题：**代理把不该走代理的流量也转走了**）
4. **检测结果的提示语有讲究**：微信要求「仅需提示用户所发布内容含违规信息即可」——
   不能提示具体原因。所以只弹「内容含违规内容，无法分享」。

## 今天最值钱的两条

**① 发布了才知道的规则，比代码本身更容易卡住。**

今天三分之一的时间花在「平台规则」上：名称不能像机构名、UGC 必须接内容安全、
隐私指引不填发不出去、「代码质量」红着也能提交但「隐私指引」不填不行……
这些都是**代码写得再好也绕不过去**的。以后做小程序，第一天就该把这些查清楚。

**② 「用户能发布出去的内容」是一条很宽的线。**

我原来觉得「我们又不上传用户的原图，只传处理后的图纸数据」就不算 UGC。
但审核的判断标准是「**好友能不能看到用户生成的内容**」——能，就是 UGC。
所以只要做分享，就得接内容安全，不管传的是原图还是衍生物。
